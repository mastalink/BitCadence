BITCADENCE / USER GUIDE

Get comfortable with BitCadence

Give your AI helpers a clear job. See what is happening. Stay in control of what happens next.

Start with the short guides below. The complete references are here for a particular command, option or screen.

Your first useful task

  1. Install and open BitCadence. Start the local gateway and open the console. Prefer the Windows desktop app for a window and tray icon.
  2. Connect the console. Demo mode is simulated; a connected console works with your real board.
  3. Connect an AI app and check Helpers. Connecting an app and having a worker ready to take jobs are different steps.
  4. Ask for something. Describe a small task, inspect the proposed steps, then approve and start. Drafting alone does not run the plan.
  5. Follow the result on Home. Approve only what you intend to authorize, then inspect the recorded result.

Prefer a single walkthrough? From installed to your first result takes you through it. Prefer the terminal? Everyday commands covers the short words.

Three things that make the system easier

  • Choose the everyday workspace. The console is the main browser entry. Administration groups credential controls and specialist links to the retained /dashboard. The desktop manager runs local components; the GUI reference explains each scope.
  • Start small and check the outcome. A drafted plan, a submitted job, an online worker and completed work are different states. Look for a recorded result before calling a task finished.
  • Keep advanced details close, not in your way. Open advanced controls when a task needs them. The references keep the detail available without making every first step technical.

Explore safely

The console labels simulated data Demo. Use it to learn the layout; it does not prove a real worker is connected. Do not put real credentials into examples or screenshots. Copying a documentation code block only copies its text.

Approval, stop, retry, token and deletion controls can change real work. Stop work… reviews the halt effect before Stop work now. Resume permits new work; halted attempts need Retry. These guides describe the UX source branch and fixture checks, not a claim that your running app was updated.
