2. Understand the names

  • Hub: the supervisor's desk. It holds the work list and checks approval.
  • Worker: a separate computer that does assigned work.
  • Reviewer: another separate computer that receives follow-up work. Its name does not give it human approval authority.
  • S3: Amazon's file storage. It keeps the audit evidence.
  • SSM tunnel: a private connection from your laptop to the hub. It lets you open the application without exposing its web port to the internet.

5. Stop work, then stop the computers

These are two separate actions.

  1. To halt governed work: Settings → Gateway controls → Stop work → Save gateway settings.
  2. To stop cloud compute charges, run the command below. Closing your browser does not stop the machines.
powershell -File scripts/cloud_lab.ps1 -Action Stop
powershell -File scripts/cloud_lab.ps1 -Action Status

Expected: hub, worker and reviewer all say stopped. Retained disks, secrets and stored files still cost money. The stop control does not erase the audit history.

Answers to the obvious follow-up questions

Is this just a dashboard? No. The demonstrations exercise server-side approval and ownership checks, not only visual status changes.

Can it stop anything? It stops governed attempts and rejects stale results. Our SDK workers check permission between work units. It does not magically undo an external action that already happened.

Is it production-ready? This is a verified test lab. Production review findings, reliable startup, non-root operator access and high availability remain work to finish.

Where is the evidence? Job history in the app and versioned records in S3. Cloud acceptance checked active one-day COMPLIANCE retention. That is a storage guarantee, not a claim of regulatory certification.
